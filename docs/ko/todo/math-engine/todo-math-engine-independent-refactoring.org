* 목적

Math Engine을 BYUL 내부 module이나 임시 root target이 아니라 독립 Git 저장소와 독립 SDK
제품으로 먼저 완성한다. Local checkout 이름은 =math_engine_env=, CMake project·package와
native artifact 이름은 =math_engine=을 사용한다. BYUL은 완료된 installed SDK만 소비하며
Math Engine source, private header, build tree와 Python environment를 소유하지 않는다.

이 문서는 BYUL 저장소에서 독립 저장소 분리와 consumer 전환을 조정하는 리팩토링 계획의
원본이다. Math Engine 저장소가 생성된 뒤의 기능 구현 TODO는 Math Engine 저장소가 소유하고,
이 문서는 cross-repository handoff, BYUL 소비 전환과 legacy 제거 gate만 소유한다.

#+begin_quote
기존 BYUL 코드를 먼저 바꾸지 않는다. 독립 Math Engine SDK를 완성하고 검증한 뒤 BYUL을
consumer로 전환한다.
#+end_quote

* 최우선 결정

- Math Engine은 BYUL과 별도 Git history, branch, version, release와 issue 경계를 가진다.
- 초기 작업 branch는 Math Engine 저장소의 =codex/math-engine= 후보로 만들되 실제 branch
  생성·remote·push는 저장소 생성 범위와 사용자의 승인을 확인한 뒤 수행한다.
- Native SDK는 같은 public C ABI를 제공하는 shared/static library를 함께 설치한다.
- 기본 CMake consumer target은 shared =MathEngine::MathEngine=, static 선택 target은
  =MathEngine::MathEngineStatic=이다.
- Python binding과 PySide6 계산기는 shared runtime을 사용한다.
- Python GUI standalone 배포는 =cx_Freeze=를 사용한다.
- BYUL, Balix, Entity, Projectile, Ground는 SDK handoff 이전에 Math Engine adapter나 임시
  계산 사본을 구현하지 않는다.
- Navsys는 현재 Math Engine consumer가 아니며 dependency를 추가하지 않는다.
- 기존 =byul_math_*= 이름과 BYUL public type을 독립 Math Engine의 안정 ABI로 고정하지
  않는다. 독립 public identifier는 =math_engine_*=를 사용한다.

Math Engine의 최소 target-based CMake 원본을 직접 작성하고 그 provenance를 기록한다.

Calculator는 widget에서 CFFI pointer를 직접 다루지 않고 application service와 Python facade를

plugin을 load해야 한다.

각 단계는 다음 항목을 결과 Org 또는 기계 판독 manifest에 기록한다.

#+begin_src text

generated binding, package staging과 TODO 상태를 병렬 작업자가 동시에 수정하지 않는다.
