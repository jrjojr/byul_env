* 문서 책임과 P0 결함

=byul/navsys/dstar_lite/dstar_lite_key.h=의 D* Lite lexicographic key value API를
재설계한다. 공통 기준은 [[file:todo-navsys-industry-api-baseline.org][Navsys 업계 API 기준]]이다. 현재 approximate equality,
exact ordering, bitwise hash가 서로 다른 동치관계를 사용하여 ordered/unordered container와
Python hash 계약을 동시에 위반한다.

* 알고리즘·언어 기준

- Koenig/Likhachev의 [[https://publications.ri.cmu.edu/d-lite][D* Lite 원 논문]]에서 key는
  =(k1,k2)= lexicographic ordering으로 open list 순서를 정한다. 근사 동등성은 queue의
  equivalence가 아니다.
- C++ comparator는 strict weak ordering이어야 한다. C++ 표준
  [[https://eel.is/c++draft/associative.reqmts][associative requirements]]와
  [[https://wiki.sei.cmu.edu/confluence/display/cplusplus/CTR57-CPP.+Provide+a+valid+ordering+predicate][SEI CTR57-CPP]]를 적용한다.
- equal object는 같은 hash를 가져야 한다. 근사 비교는 비추이적일 수 있으므로 별도
  =is_close= 진단 함수로만 제공한다.

* 현행 구현 근거

- =equal=은 scalar tolerance 비교다.
- 구현은 Numal =scalar.h=의 =scalar_equal=을 호출한다. 이 결합은 D* Lite key의
  동치관계를 외부 범용 tolerance 정책에 맡기는 구조이므로 제거한다.
- =compare=는 먼저 approximate equal이면 0을 반환하고, 아니면 exact
  lexicographic을 사용한다. A≈B, B≈C, A!≈C가 가능하다.
- =hash=는 exact float bit 조합이므로 approximate-equal key가 다른 hash를 가질 수
  있다. =-0/+0=과 NaN도 canonical policy가 없다.
- 작은 8-byte value를 create/copy에서 heap allocation하며 C++ =new= 실패 채널이 없다.

* 현행 선언 전수 목록과 처분

| 선언 | 현재 의미/결함 | 처분 |
|------+----------------+------|
| =dstar_lite_key_t= | 공개 ={float k1,k2}= value layout | keep |
| =dstar_lite_key_create= | heap zero-key, OOM 채널 없음 | deprecate-forward |
| =dstar_lite_key_create_full= | NaN/Inf 검증 없는 heap 생성 | deprecate-forward |
| =dstar_lite_key_copy= | tiny value heap 복제 | deprecate-forward |
| =dstar_lite_key_destroy= | heap family 종결 | keep |
| =dstar_lite_key_equal= | approximate, hash/order와 불일치 | deprecate-forward |
| =dstar_lite_key_compare= | 비추이 approximate equivalence | deprecate-forward |
| =dstar_lite_key_hash= | equal⇒same-hash 위반 | deprecate-forward |

새 init/exact/is_close/metadata 함수는 =add=다. =float=를 =double=로 직접 바꾸는 후보와
field layout 변경은 =abi-major=다. D* Lite 내부 전용으로 완전히 숨기는 선택도 ABI 2
consumer 조사 뒤 별도 =internalize= 결정을 내린다.

* 목표 수치 계약

- queue에 들어가는 canonical key는 finite 또는 algorithm이 사용하는 positive infinity만
  허용할지 결정한다. D* Lite는 초기 g/rhs infinity가 key에 나타날 수 있으므로
  =+Inf=를 valid maximum sentinel로 허용하고 NaN, =-Inf=를 거부하는 안을 우선한다.
- =-0.0f=는 =+0.0f=로 canonicalize한다.
- exact equality는 canonical field equality, compare는 exact lexicographic -1/0/1,
  hash는 두 canonical field와 exact equality를 공유한다.
- approximate comparison은 =abs_tol=와 =rel_tol=를 caller가 명시하며 queue/hash/equality,
  termination 조건에는 사용하지 않는다.
- ABI 1 public layout의 size/align/offset을 manifest로 고정한다.

- 2026-07-25 현행 8개 선언의 ABI 1.x 처분을 표와 같이 고정했다. 공개
  ={float k1, k2}= layout은 size 8, align 4, offset 0/4이며 create/create-full/copy는
  caller-owned heap allocation, destroy는 NULL-safe, copy(NULL)는 NULL이다.
- legacy equal/compare는 =scalar_equal= 상대 tolerance를 equivalence로 사용한다.
  따라서 근접한 서로 다른 key가 compare 0이면서 서로 다른 hash를 가지며, tolerance
  chain은 비추이적이다. =+0/-0=도 equal/compare 0이지만 bit hash는 다르다.
- legacy create-full은 NaN과 양·음 infinity를 모두 보존한다. =scalar_equal= 특성상
  finite와 양·음 infinity도 같은 두 번째 성분을 가지면 equal/compare 0이고, NaN도
  같은 두 번째 성분의 임의 key와 compare 0이 된다. 이는 ordered/unordered container
  계약과 D* Lite의 exact lexicographic ordering에 사용할 수 없다.
- 실제 planner는 infinity가 아니라 =FLT_MAX=를 g/rhs sentinel로 사용한다. Canonical
  key domain은 finite과 =+Inf=를 허용하고 NaN과 =-Inf=를 거부하며, =-0=은 =+0=으로
  canonicalize한다. Exact equality/order/hash만 container identity로 사용하고 tolerance는
  명시적 진단 함수로 분리한다.
- MinGW static D* Lite key corpus에서 layout, NULL, allocation/copy, tolerance chain,
  zero, infinity와 NaN 동작을 고정했고 CMU D* Lite 정의의 exact lexicographic reference와
  legacy 결과 차이를 확인했다. MinGW/MSVC key gate 36/36과 D* Lite 전체 123/123이
  통과했다. 설치 C17 consumer에도 layout과 legacy equal/compare/hash 불일치 fixture를
  추가했다.
- 앞선 =coord.h=의 =navsys_status.h= 공개 의존성을 legacy module/test target이 전달받지
  못하는 include graph 결함을 발견했다. =coord=/=navsys= target의 public usage requirement를
  선언하고, 직접 header를 소비하는 기존 target을 위해 project scope에 =byul/navsys=
  public-header root를 한 번 제공했다. MinGW 전체 SDK build/install과 설치 SDK C17/C++17
  consumer까지 통과했다.

*** ABI 1 migration

| legacy API | replacement | ABI 1.x semantic migration |
|------------+-------------+------------------------------|
| =create/create_full= | =init/create_ex= | symbol은 유지하되 NaN/-Inf를 NULL로 거부하고 -0을 +0으로 정규화한다. |
| =copy= | =copy_ex= | symbol은 유지하되 source를 canonical validation하고 -0을 +0으로 정규화한다. |
| =equal= | =equal_exact= 또는 =is_close= | container identity는 exact로 forward하며 근사 판정은 tolerance를 명시해야 한다. |
| =compare= | =compare_exact= | exact lexicographic order로 forward한다. Legacy signature는 invalid input에서 0 fallback을 유지한다. |
| =hash= | =hash_exact= | canonical hash로 forward하여 +0/-0과 exact equality가 같은 hash를 가진다. |

- 위 legacy symbol은 ABI 1.x에서 제거하지 않고 =BYUL_DEPRECATED= migration target을
  header에 제공한다. ABI 2 전까지 source/binary compatibility entry point로 남긴다.
- =is_close(lhs,rhs,absolute_tolerance,relative_tolerance,out)=는 finite nonnegative tolerance만
  받는다. 각 finite 성분은 =abs(a-b) <= max(abs_tol, rel_tol*max(abs(a),abs(b)))=로
  판정하고 =+Inf=는 =+Inf=에만 close다. 이 관계는 비추이적이므로 진단/수렴 보고에만
  쓰며 container identity/order/hash와 algorithm termination에는 사용하지 않는다.
