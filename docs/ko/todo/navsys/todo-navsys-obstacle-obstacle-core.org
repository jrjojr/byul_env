* 업계 비교와 target API

- [[https://www.sqlite.org/c3ref/sqlite3.html][SQLite opaque handle]]처럼 public resource layout을 숨긴다.
- [[https://recastnav.com/classdtNavMeshQuery][Detour]]와 공통 baseline처럼 raw container 대신 capacity/count/status를 사용한다.
- [[https://gdal.org/en/stable/api/gdal_alg.html][GDAL rasterization]]처럼 line/polygon policy는 generator layer가 소유하고 core는 coordinate
  set lifecycle/mutation만 담당한다. neighbor/degree helpers는 navgrid/shared geometry로 이동 후보이다.

3단계는 owner가 없는 =byul_grid_rect_t=를 먼저 선언하지 않고 이미 승인된 scalar extent와

** 확정한 계약

- extent는 =x0=에서 =x0 + width=, =y0=에서 =y0 + height= 사이를 정규화한
  half-open 영역이다. 음수 width/height는 기존 ABI처럼 반대 방향 영역을 나타내고 0인 축은
  빈 영역이다. 경계 계산은 64-bit 중간값을 사용하여 =int= 덧셈 UB를 만들지 않는다.
- =obstacle_block_coord=는 extent 밖 좌표를 거부하며 blocked set에는 extent 내부 좌표만
  남긴다.
- legacy =obstacle_set_origin=은 기존 blocked 좌표의 상대 위치를 보존해 새 origin으로
  translate한다. 좌표 overflow 또는 allocation 실패 시 void API는 object 전체를 그대로
  보존한다.
- legacy width/height setter는 새 extent 밖 blocked 좌표를 clip한다. 임시 hash를 완성한 뒤
  한 번에 commit하므로 실패하면 extent와 blocked set을 모두 보존한다.
- Obstacle은 thread-compatible이며 mutation에는 외부 동기화가 필요하다. 성공한 mutation은
  =obstacle_get_blocked_coords=로 얻은 borrowed hash와 그 내부 view를 무효화할 수 있다.
- Copy는 독립 blocked set을 소유하고 equality는 extent와 blocked key set을 함께 비교한다.
  Equal object는 같은 =obstacle_hash= 값을 가져야 한다.

* DONE 3단계: checked lifecycle·mutation·buffer API

** 실행

- =obstacle_create_checked=, =obstacle_copy_checked=, =obstacle_set_blocked=와
  =obstacle_export_blocked=를 additive ABI 1.x symbol로 구현한다.
- allocation/hash failure와 C++ exception을 status로 변환하고 rollback한다.
- legacy =obstacle_create=, =obstacle_create_full=, =obstacle_copy=,
  =obstacle_block_coord=과 =obstacle_unblock_coord=만 이 단계의 canonical checked core로
  forwarding한다. Range/straight helper와 navgrid apply/remove는 4~5단계에 유지한다.
- 신규 선언은 직접 include, 한국어 Doxygen, nullable/lifetime/error/side-effect와
  buffer/capacity/count metadata를 완전하게 기록하되 기존 Header debt의 전면 정리는
  6단계에 유지한다.

** 확정 계약

- 2단계에서 승인한 signed normalized extent를 유지한다. 음수 width/height는 반대 방향
  half-open extent이고 0인 축은 빈 영역이다.
- =INVALID_ARGUMENT=, =OUT_OF_MEMORY=, =CORRUPT_STATE=과 extent 밖 좌표의
  =NOT_FOUND=를 구분한다. 음수 status에서는 object와 모든 output을 보존한다.
- 이미 요청한 blocked 상태이면 =OK=와 =out_changed=false=, 실제 mutation이면 =OK=와
  =out_changed=true=를 반환한다.
- =out_coords=NULL, capacity=0=은 count query다. 부족한 buffer는 건드리지 않고
  =INCOMPLETE=와 전체 필요 count를 반환하며 export 순서는 보장하지 않는다.
- Legacy block은 =status == OK=를 반환해 unchanged 성공 의미를 유지하고 legacy unblock은
  =status == OK && changed=를 반환해 실제 제거 의미를 유지한다. Checked create/copy 실패는
  legacy NULL로 mapping한다.
- 기존 =malloc/free= allocator pair는 유지한다. Fault fixture 통과만을 위해 production
  allocator를 바꾸거나 =BYUL_TESTING= hook을 추가하지 않는다.
- 기존 =obstacle_get_blocked_coords=는 ABI 1.x 호환을 위해 유지하지만 신규 API와 consumer는
  internal hash pointer를 사용하지 않는다.

** 완료 조건

- OOM/invalid/corrupt/not-found/unchanged를 구분하며 실패 시 output/object 보존 조건을
  지킨다.
- 신규 declaration, definition과 root shared export가 일치하고 Header audit 신규 오류와
  CFFI stale generation이 0건이다.
- 신규 API와 전환한 consumer는 internal hash pointer를 노출하거나 사용하지 않는다.

** 검증

- NULL/empty, zero/exact/undersized buffer와 output sentinel 보존을 검사한다.
- 현재 test executable이 주입할 수 있는 모든 C++/hash allocation index에서 status,
  rollback, exception containment와 leak을 검사한다. =malloc= NULL을 직접 주입하지 못한
  profile은 production hook으로 숨기지 않고 별도 test-only 방법 또는 미검증 제한으로
  기록한다.
- MSVC Release allocation fixture의 obstacle 제외를 제거하고 동일 revision/patch의
  Virtual Yard GCC·Clang ASan/LSan/UBSan을 실행한다.
- Module static, root =byul= shared, root =test_byul=, export inventory와 clean installed-SDK
  C/C++ consumer에서 old/new 결과를 비교한다.
- Wrapper header audit, CFFI =--check=와 실제 root library load에서 신규 status+out symbol을
  분류·검증하며 generated 영역은 직접 수정하지 않는다.

* DONE 5단계: navgrid overlay/provenance

** 실행

- merge policy, bounds/resize, changed count와 all-or-nothing/partial guarantee를 확정한다.
- overlay token/before-image로 다른 obstacle/terrain/maze source를 보존한다.
- remove는 token owner/lifetime/version mismatch를 status로 진단한다.

** 완료 조건

- overlapping source를 임의 순서로 apply/remove해도 남은 source가 유지된다.
- cancellation/OOM mid-apply가 약속한 rollback을 수행한다.

** 검증

- multi-overlay/custom terrain/nonzero origin/fault/cancel tests와 ASan/LSan을 실행한다.

** 확정 계약

- =obstacle_apply_to_navgrid_checked=와 =obstacle_remove_from_navgrid_checked=를 additive
  ABI 1.x symbol로 추가했다. apply options와 overlay token은 =struct_size/abi_version=을
  가지며 unknown version과 merge policy는 =UNSUPPORTED=로 진단한다. merge policy 저장 필드는
  future integer 값을 C++ invalid-enum UB 없이 거절하도록 =uint32_t=로 고정했다.
- 현재 merge policy는 기존 terrain을 보존하는 =PRESERVE_BASE= 하나다. Obstacle blocked 좌표가
  navgrid bounds 밖에 하나라도 있으면 resize나 partial apply 없이 =NOT_FOUND=를 반환한다.
  성공 시 changed count는 해당 overlay가 실제로 새로 막은 cell 수다.
- Token은 navgrid owner generation과 overlay id를 함께 보관한다. 다른 grid, copy로 생성된 grid,
  이미 제거된 token에는 =INVALIDATED=를 반환하며 실패 시 token, output count와 grid를 보존한다.
  성공한 remove만 token의 owner/id를 0으로 만들어 재사용을 막는다.
- 각 overlay layer는 독립적으로 합성된다. 겹치는 obstacle을 임의 순서로 제거해도 다른 overlay와
  원래의 custom terrain이 유지된다. Legacy void apply/remove는 ABI 1.x source-key layer에
  forwarding하여 기존 반복 apply/remove 동작과 overlap 보존을 유지하고 ABI 2 제거 대상으로
  deprecate했다.
- Cancellation callback은 call-scoped다. true는 =CANCELLED=, callback exception은
  =CALLBACK_FAILED=이며 validation, allocation, commit 전 구간의 실패는 all-or-nothing이다.
